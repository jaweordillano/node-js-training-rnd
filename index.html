Self-paced course

Node.js Developer Training

Go from basic programming to building, validating, testing and version-controlling a typed REST API on Node.js, at your own pace.

1.Welcome

This course is for developers who know basic programming and are new to Node.js. You do not need to know Git, modern JavaScript, TypeScript or SQL already. Each is taught from the start, when you need it.

Every module is a page you can follow on your own. It explains the idea, shows you the steps and the commands, tells you what you should see, and lists what to do if you don't see it.

  • 10 modulesabout 80 hours
  • ~4 hoursa day is a good pace
  • Free toolsno Docker, no licences
  • Hands-onevery module ends in something you built

What you'll build

You will grow one Task API across the course, from a first Express server to a typed, validated and tested API backed by a real database. You finish with a capstone API in a domain of your own.

A note on words

On these pages a module is a lesson in this course (M01 to M10), not a JavaScript or Node.js module. Modules M02 and M03 teach what a JavaScript module is: named vs default exports, ESM vs CommonJS.

2.How the course works

  1. Open a module and read its time plan. It splits the module into stages, each with a time estimate, so you can plan around your day.
  2. Work through the stages in order. Type the commands yourself rather than pasting them where you can. You learn more that way.
  3. Use the checkpoints. After each stage a short box says what you should be able to see or do. If you can't, stop there and use the troubleshooting section before moving on.
  4. Finish with "You're done when". Every module ends with a checklist. Tick everything before starting the next module.

Later modules build on earlier ones, so take them in order. The Task API you start in M05 carries forward through M07, M08 and M09.

Pause any time

Stages are small on purpose. Stop at a checkpoint, commit your work, and pick up the next day. Your progress is your Git history.

4.Your repo

You do your work in your own public GitHub repository, which you create in M01. Use it for everything you build in the course, so your progress and history are in one place.

Why public?

Public repos are free, work the same for everyone, and let you share your work. Private repos can limit some GitHub features depending on your plan.

Never commit secrets

Passwords, tokens and API keys do not go in a repo, least of all a public one. M01 shows you how to keep them out.

6.When you're stuck

  1. Re-read the last checkpoint. Is what you see different from what it says you should see?
  2. Open the module's troubleshooting section. The common problems are there.
  3. Read the error message from the top. The first line usually names the real problem.
  4. Search the exact error message. Add the name of the tool, for example git or nvm.
  5. Still stuck? Ask whoever runs your course, and include the command you ran, the full error, your operating system and what you already tried.
