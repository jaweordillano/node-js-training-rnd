Training programme

Node.js Developer Training

Go from basic programming to building, validating, testing and version-controlling a typed REST API on Node.js, in four weeks.

1.Introduction

This programme is for developers who know basic programming concepts and are new to Node.js. Git, modern JavaScript, TypeScript and SQL are all taught from first principles, so you do not need them already.

The format is build-to-teach. You are not walked through the material. Instead you work toward each stage's deliverable from a brief, and you write up how you did it as you go. That write-up is what teaches the next cohort.

  • 4 weeksabout 4 hours a day
  • 10 modulesabout 80 hours
  • 4 gatesFriday pass/fail checkpoints
  • Free toolsno Docker, no licences

By the end you will have built a Task API with Express, SQLite, Prisma, Zod and Jest, and an independent capstone API.

A note on words

A module on these pages is a training stage (M01 to M10), not a JavaScript or Node.js module. Stages M02 and M03 are where you learn what a JavaScript module is: named vs default exports, ESM vs CommonJS.

2.How a stage works

  1. Read the brief. It gives the objective, scope, stack constraints, the named deliverable, a lab and a definition of done. It contains no lesson, steps or solutions.
  2. Build and write up together. Fill in the write-up while you build, not after it works.
  3. Your trainer reviews both. The question is not only "does it work?" but "could someone else learn from this?"
  4. Revise. Fix what the review finds, in the build and the write-up, before the next stage.
  5. The pair joins the content library. Your trainer decides what carries into the next cohort.

Review happens at the end of every stage, not only at the end of the course.

4.Repository to work with

There are two repositories, and it helps to keep them apart.

RepositoryWhat it is for
strat-training/node-js-training-rnd The programme itself: the briefs, task checklists, write-up templates and these pages. You read from it and write up your stages in it.
Your own public training repo Where your Node.js code lives. You create it in M01 and link it from the header of each write-up.

Why public?

Branch protection on private repos depends on the GitHub plan, and a public repo avoids that dependency entirely. Public training repos are the default for every module.
